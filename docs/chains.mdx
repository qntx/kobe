Where a wallet appears without a path of its own (Trust Wallet in
particular) it derives a single account at index `0`.

## Cosmos presets

`--chain`: `cosmos`, `osmosis`, `celestia`, `dydx`, `sei`, `akash`, `terra`,
`secret`, `kava`, `injective`, `evmos` — each fixes the BIP-44 coin type and
bech32 HRP; `--hrp` overrides only the prefix.

## Kaspa `--encoding`

`standard` addresses carry the x-only schnorr public key; `onekey` carries
the BIP-341 key-path-tweaked key used by the OneKey default Kaspa account
type. The exported `private_key` is the untweaked raw key either way.

## Solana `root`

Ledger Live's `solanaMain` derivation mode — a single, non-iterating account
at `m/44'/501'` (no `{i}`).

## Cardano `--master`

The CIP-3 master-key algorithm: `icarus` (Yoroi/Daedalus Shelley, Trezor
<24 words), `ledger` (Ledger devices), `icarus-trezor` (Trezor 24-word
mnemonics). Custom `--path` must keep the `m/1852'/1815'/a'/0/n` shape; the
stake key is always derived at `m/1852'/1815'/a'/2/0` for the same account
and emitted in `extra.stake_address`.

## TON options

`--contract` selects the wallet contract (`v4r2` subwallet
`698983191 + workchain`, `v5r1` `networkGlobalId ^ clientContext`);
`--testnet` emits testnet-only addresses (`0Q…`/`kQ…`); `--bounceable`
emits bounceable ones (`EQ…`/`kQ…`).

## Spark caveats

- The official Spark SDK derives its seed with `mnemonicToSeed(mnemonic)` and
  never applies a BIP-39 passphrase, so a kobe Spark address generated with
  `-p` is only reachable in the SDK by passing that seed directly.
- `private_key` is only the identity key at `m/8797555'/{account}'/0'` —
  Spark wallets also use signing/deposit/static-deposit/HTLC keys at `/1'`
  through `/4'`; restore a Spark wallet from the mnemonic, not from this key.
- Spark is not Lightning: kobe derives no Lightning node keys, and Spark L1
  deposit addresses depend on operator keys and cannot be derived offline.

## Output formats

Every account emits `path`, `address`, `public_key`, and `private_key` (the
chain's wallet-import encoding):

| ------------------------------------ | ---------------------------------------------------- | -------------------------------- | --------------------------------- |

| bitcoin-cash                         | CashAddr `bitcoincash:q…`                            | compressed WIF                   |                                   |
| evm                                  | EIP-55 `0x…`                                         | `0x` hex                         |                                   |
