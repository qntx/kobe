```text
kobe [--json] [-r|--reveal] <COMMAND>
kobe mnemonic [-w 12|15|18|21|24]
kobe <chain> [shared flags] [chain flags]
```

Every chain command shares the same flags:

| Flag               | Description                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| `-m, --mnemonic`   | Import a mnemonic; `-` reads one line from stdin. Words may be unique ≥4-letter BIP-39 prefixes. |
| `-w, --words`      | Word count when generating: 12/15/18/21/24 (conflicts with `-m`).                                |
| `-p, --passphrase` | BIP-39 passphrase; `-` prompts on the terminal without echo (asks twice when generating).        |
| `-s, --style`      | Style id or alias, case-insensitive (see [Chains](/docs/kobe/chains)).                           |
| `--path`           | Custom path template; `{i}` marks the iterated index (conflicts with `-s`).                      |
| `-i, --index`      | First iterated index (defaults to the style's `start`).                                          |
| `-c, --count`      | Number of accounts (default 1).                                                                  |
| `--qr`             | Print a terminal QR for every derived address (ignored with `--json`).                           |
| `--json`           | Machine-readable output.                                                                         |
| `-r, --reveal`     | Show mnemonic and private keys (hidden by default).                                              |

Without `-m` the command generates a fresh mnemonic. `kobe mnemonic` always
prints the phrase — it is the output.

## Output

Human mode prints a header block (chain options as human labels, `Mnemonic`,
`Passphrase` when set, `Style` with wallet labels), then one block per
account (`Index` when iterating more than one, `Path`, `Address`, chain
extras like `Stake Address`, `Private Key`). Secrets render as
`(hidden; pass -r / --reveal)` unless `-r` is passed; the public key is not
shown in text mode. Labels are cyan-bold, addresses green, hints dimmed
when writing to a TTY.

```text

      Network      mainnet
      Address Type P2WPKH (Native SegWit)
      Mnemonic     (hidden; pass -r / --reveal)
      Style        standard (Sparrow, Electrum, BlueWallet, Trust Wallet)

      Path         m/84'/0'/0'/0/0
      Address      bc1qcr8te4kr609gcawutmrza0j4xv80jy8z306fyu
      Private Key  (hidden; pass -r / --reveal)

```

`kobe mnemonic` prints a labelled block on a TTY and the bare phrase on a
pipe (`kobe mnemonic -w 24 | kobe bitcoin -m -`). `--seedqr [standard|compact]`
requires `--reveal` and encodes the mnemonic as a SeedQR (SeedSigner format).

`--json` emits pretty-printed JSON with the same fields as before:

`--json` emits:

```json
{
  "chain": "cardano",
  "options": { "master": "icarus", "network": "mainnet" },
  "style": "standard",
  "template": "m/1852'/1815'/{i}'/0/0",
  "mnemonic": "…",            // only with --reveal
  "passphrase": false,
  "accounts": [
    {
      "index": 0,             // null when the template has no {i}
      "path": "m/1852'/1815'/0'/0/0",
      "address": "addr1…",
      "public_key": "…",
      "private_key": "…",     // only with --reveal
      "stake_address": "stake1…"   // chain extras are flattened per account
    }
  ]
}
```

Errors exit non-zero; in `--json` mode the error is `{"error": "…"}` on
stdout with exit code 1. Mnemonic errors name the 1-based word position
(`word 3 is not a BIP-39 English word`) and never echo the input.

`-m -` reads exactly one line from stdin into a zeroizing buffer. Word tokens
may be exact BIP-39 English words or unique prefixes of at least 4 letters
(`aban aban … abou` imports the `abandon … about` test vector).

## Mnemonic camouflage

`kobe mnemonic encrypt` disguises a mnemonic as a different, fully valid
BIP-39 mnemonic; `decrypt` recovers the original with the same password
(algorithm v1, byte-compatible with kobe v1.0.0–v4.0.0):
`E' = E XOR PBKDF2-HMAC-SHA256(password, "kobe-mnemonic-camouflage-v1",
600_000, |E|)`.

- **Security = password strength.** The camouflaged phrase gives attackers
  an offline oracle: each guess costs 600k PBKDF2 iterations plus a BIP-39
  derivation and a balance check. Use ≥64-bit password entropy (six+
  diceware words). `encrypt` refuses zxcvbn scores below 3 unless
  `--allow-weak-password` is passed.
- **Global fixed salt.** The output must be a bare mnemonic — there is
  nowhere to store a random salt, so every user shares one salt. Strong
  passwords are the only defence.
- **Never reuse a password across mnemonics** (two-time pad:
  `M1' XOR M2' = E1 XOR E2`).
- **No integrity check, by design.** A wrong password yields a different
  valid (empty) wallet — that is the deniability. The printed `Fingerprint`
  (the BIP-32 master fingerprint, not secret) is the correctness check:
  verify it matches your records before revealing.
- **NFC rule.** Passwords are raw UTF-8 bytes. `encrypt` requires the NFC
  form so the same phrase reproduces under any input method; `decrypt`
  accepts raw bytes for compatibility with mnemonics camouflaged by kobe ≤
  v4, and warns when the password is not NFC.
- **Alternatives.** BIP-39 passphrases give the same decoy-wallet effect
  with weaker KDF (2048 iterations) but wallet support everywhere; if the
  goal is resilience rather than disguise, prefer SLIP-39 or Seed XOR.

```text
$ echo "correct horse battery staple" | kobe mnemonic encrypt -m <PHRASE> --password-stdin

      Mode         encrypt
      Words        12
      Strength     strong (zxcvbn 4/4)
      Camouflaged  (hidden; pass -r / --reveal)
      Fingerprint  a5c0221c (original wallet — note it separately)
      Verified     round-trip ok
```

Passwords are never taken on the command line: the default is a hidden
terminal prompt (`Password:`/`Confirm:`), `--password-stdin` reads one
line for scripts (strips a single trailing newline; conflicts with
`-m -`).

## `kobe upgrade`

Self-upgrade via the official installer (feature `upgrade`, on by default;
`update` alias). Behaviour depends on how the running binary was installed:

- **Installer-managed** (`sh.qntx.org` receipt present): fetches the locked
  release metadata, verifies hashes, and installs in place.
- **Cargo-installed** (`cargo install kobe-cli`): reports
  `kobe was installed with cargo; run: cargo install …` — upgrading is
  cargo's job.
- **Unmanaged** (e.g. a `target/` build): same cargo-style notice.

Flags: `--check` (report only, install nothing), `--version X.Y.Z` (pin a
release instead of latest), `--force` (reinstall same version). `--json`
prints the machine-readable report.

An air-gapped or minimal build can drop the command entirely:

```sh
cargo install kobe-cli --no-default-features
```

that binary has no `upgrade` subcommand and no `upg` in its dependency tree.
